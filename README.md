# Ordo Panel — панель для переписки с клиентами через Telegram

## Устройство системы

Клиент пишет боту → Telegram шлёт вебхук на `/api/telegram/webhook` → сообщение сохраняется
в Supabase (Postgres) и файл (если есть) перезаливается в Supabase Storage → благодаря Supabase
Realtime все открытые панели сотрудников получают обновление мгновенно, без перезагрузки страницы.
Сотрудник отвечает через `/api/messages/send` → сервер вызывает Telegram Bot API → ответ уходит
клиенту от имени бота. Вход в панель — через Supabase Auth (email + пароль).

Способ получения сообщений: **webhook** (не long polling) — подходит для Vercel, так как
не требует постоянно работающего процесса.

## Как запустить

1. Установите зависимости: `npm install`
2. Скопируйте `.env.example` → `.env.local`, заполните своими ключами
3. В Supabase → SQL Editor выполните `supabase/schema.sql`
4. В Supabase → Authentication → Users создайте 2+ сотрудников (email + пароль),
   и для каждого добавьте строку в таблицу `staff_profiles` (id = id пользователя, full_name = имя)
5. Локально: `npm run dev`. На Vercel: импортируйте репозиторий, добавьте те же переменные окружения
   в Settings → Environment Variables, задеплойте
6. Подключите бота к панели по инструкции в `setup-webhook.md`

## Что оказалось сложнее всего

Синхронизация правки/удаления сообщений с Telegram — у API есть нюансы (нельзя редактировать
сообщения с файлами, есть срок в 48 часов на удаление), это не сразу очевидно.
